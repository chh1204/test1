# Roam — AI 여행 비서 MVP

여행지, 여행 날짜, 인원, 예산, 취향, 기존 숙박 예약을 바탕으로 일정을 만들고 수정하는 독립 웹앱입니다. 실제 AI API 없이 실행할 수 있는 규칙 기반 데모입니다. 기존 Speed Clicker 게임 파일은 사용하거나 변경하지 않습니다.

## 실행

Python 3가 필요합니다. 이 프로젝트 폴더에서 실행하세요.

```sh
python3 -m http.server 4173 --directory dist
```

브라우저에서 <http://localhost:4173>을 엽니다. 별도 패키지 설치, 계정, API 키는 필요하지 않습니다. 종료하려면 실행 중인 터미널에서 `Ctrl+C`를 누릅니다.

Node.js가 있다면 검증 테스트도 실행할 수 있습니다.

```sh
npm test
```

## 사용 방법

1. 여행지, 시작일과 종료일, 동행 인원, 총예산, 여행 취향을 입력합니다.
2. 기존 숙박 예약과 숙박비를 확인하거나 수정합니다.
3. 일정을 생성하고 날짜별 활동을 확인합니다.
4. 활동의 내용과 예상 비용을 수정하거나 활동을 추가·삭제합니다.
5. JSON 내보내기로 계획을 저장하고, JSON 가져오기로 다시 불러옵니다.

숙박 예약은 여행 조건에서 수정합니다. 예약에서 생성된 숙박 항목은 일정 카드에서 직접 삭제하거나 수정할 수 없습니다.

입력과 일정은 현재 브라우저의 `localStorage`에 저장됩니다. 다른 브라우저나 기기와 동기화되지 않으며 브라우저 데이터 삭제 시 사라집니다. 공유 기기에는 개인 예약 정보를 남기지 않는 것이 좋습니다. 내보낸 JSON은 사용자가 보관하는 백업입니다.

## 스위스 테스트 사례

- 기본 여행: 2027년 9월 13일~17일, 가족 4명. 여행 일정은 양 끝 날짜를 포함합니다.
- 기존 예약: 그린델발트 9월 13일 체크인, 9월 17일 체크아웃, **4박**. 예약 상태는 사용자가 입력한 내용이며 실제 숙소 시스템에서 확인한 결과가 아닙니다.
- 예산 단위: **원화, 동행 전체 기준**. 국제선 항공료를 제외한 현지 여행 예산입니다.
- 숙박비: 초기에는 미입력입니다. 예약 비용을 입력하기 전에는 전체 여행 비용을 확정할 수 없습니다.

일정 추천은 입력 조건에 따른 데모 규칙과 준비된 장소 정보를 사용합니다. 예상 비용, 이동 시간, 교통 정보는 시연용 참고값입니다. 실제 2027년 운행 시간표, 영업일, 요금, 좌석, 날씨, 예약 가능 여부는 확인하지 않습니다. 여행 전 공식 공급자의 정보를 확인해야 합니다.

## 프로젝트 구성

```text
dist/                 브라우저에서 실행하는 정적 웹앱
  index.html          앱 진입점
  style.css           반응형 화면 스타일
  assets/             로컬 시연용 사진
  js/app.js           입력·일정 편집·저장·내보내기 화면
  js/planner.js       규칙 기반 일정과 예산 계산
  js/state.js         저장 파일·공급자 출력 검증
  js/providers.js     일정 생성 공급자 경계와 지도 검색 링크
tests/                일정과 입력 검증 테스트
package.json          테스트 실행 설정
README.md             실행 방법과 연동 안내
```

`dist`만 정적 웹 호스팅에 올릴 수 있습니다. GitHub 저장소에 넣을 때는 기존 게임과 별개인 `travel-assistant/` 폴더로 추가하면 됩니다. GitHub Pages에서는 해당 폴더의 `dist` 내용을 배포 대상으로 사용합니다.

## 실제 AI 연결

`dist/js/providers.js`의 `planTrip(trip)`가 일정 생성의 경계입니다. 현재 기본 공급자는 데모이며, UI는 아래 형태의 결과를 받습니다.

```js
{
  provider,
  days,
  notes
}
```

실제 LLM을 붙일 때는 서버에 `POST /api/plan`을 만들고 요청 본문으로 `{ trip }`을 전달합니다. 서버는 검증된 결과를 같은 `{ provider, days, notes }` 구조로 반환하고, `planTrip`이 그 서버를 호출하도록 바꿉니다. 세부 필드는 현재 데모 출력과 테스트를 기준으로 맞춥니다.

API 키는 서버 환경 변수에 저장합니다. 브라우저 코드, JSON 내보내기, GitHub에 키를 넣지 않습니다. 서버는 입력 크기와 날짜·인원·예산을 검증하고, LLM 출력의 필드·날짜·비용을 검증한 뒤 반환해야 합니다. 실패 시 UI에 오류를 보여주고 사용자가 작성한 일정을 보존해야 합니다.

지도·장소 검색과 교통 데이터도 공급자 파일을 경계로 붙일 수 있습니다. 이 MVP에는 실시간 지도·교통 API가 연결되어 있지 않습니다. 장소 ID와 좌표, 노선과 시간표를 실제 제공자의 응답으로 보완한 뒤 일정에 표시하는 이동 시간과 비용을 갱신하세요. 인증, 서버 저장소, 결제, 실제 예약 변경은 포함하지 않습니다.

현재 지도 버튼은 해당 장소의 Google Maps 검색을 새 탭으로 엽니다. 지도 API를 호출하거나 경로를 검증하지는 않습니다. 사진은 [Unsplash의 그린델발트 사진](https://unsplash.com/photos/bKLEKeqxRNU)을 로컬 파일로 포함해 정적 실행에서 사용합니다.

JSON 가져오기는 10MB 이하의 지원 형식만 허용하며, 날짜·비용·활동 구조·고정 예약 일관성을 확인합니다. 추가 요청 메모는 저장되지만 자연어로 해석하지 않습니다. 스위스 외 여행지는 실제 장소를 찾는 대신 취향별 일반 활동을 제안합니다. 예약 숙박비가 미입력되거나 숙소를 아직 정하지 않은 숙박일이 있으면 총액이 불완전하다고 표시합니다.
